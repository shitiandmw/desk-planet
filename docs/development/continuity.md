# 长期任务接续记录

目标：按来源知识库和开发清单，持续推进可玩的六时代单机文明经营闭环。每轮交付可试玩版本，并继续下一项；当前不需要重新确认日常本地开发与验证。

## 当前基线 0.2

- 可玩到机械 / 工业起步；30 项测试，两条经济路线、真实四章 UI 流程、v1 / v2 存档和离线导入已验证。
- `docs/development/browser-playthrough-v02.json` 保存实际按钮流程，`balance-v02.json` 保存两条经济路线。
- `tests/fixtures/save-v1-construction.json` 是 v1 格式的中途施工兼容样本；`save-v2-industrial.json` 来自实际经济动作脚本，可用于后续迁移回归。
- 开发服务 `woodland-demo`：`npm run dev`，端口 5187。稳定试玩 `planet-stable` 使用 `output/planet-stable/index.html`，仍在 5186，保留用户原有网址与存档。长驻服务继续使用 Agent Tower 工具。
- 树木、完整球体、水面、实体云和自由旋转是已确认视觉基准；不恢复透明云缘 Sprite。

## 下一项：U01 升级与搬迁

拟先做原地改良与搬迁，拆迁随后结合恢复路径单独验证。

- 升级应占用建造工、预留材料、暂停该设施生产，完成后才增加能力；取消仅退未用材料。
- 住房和储存升级期间保留旧容量，完工增加容量，避免施工让存档人口突然超过住房。
- 升级需要低阶设施外观继续可辨，并增加真实构件；地块占地尽量保留。
- 搬迁使用相同球面预览，检查碰撞时排除自身；确认时收取明确费用，保留设施 ID、居民岗位、住房和累计生产。取消预览不改变经济。
- 初始设施的 v2 加载器要求固定原始 siteId，因此搬迁必须伴随有测试的存档结构迁移，不能只修改渲染位置。
- 当前施工队列按建筑数组顺序排列。升级老建筑时要增加独立的工程顺序，避免插队。
- 目前机械成果的产能加成依赖 `finished`。扩展章节前，应改为独立的已达成里程碑或 `chapter >= 4`，避免增加章节反而取消旧玩家的成果。
- 保留可恢复供给；拆迁不能让玩家因为移除基础食物 / 建材设施而永久卡死。

## 后续：E01 能源

工业能源应显示供给、需求、受影响设施与优先级。新耗能设施 / 电气升级在能源解锁后引入，已存在的手工 / 机械产业保留无电恢复路线。不要把观赏天气开关直接当作经济能源输入。

## 验证与记录

每轮补实际发现的问题和修订原因；不把功能可完成冒充真人趣味性已验证。改动规则后跑相关测试与数值路线，改动画面后看实际输出。浏览器用独立会话并关闭自己创建的会话。

## 发布与回退

通过本轮检查后运行 `npm run stage:stable`，保存不可覆盖的版本快照并更新稳定 HTML；每次发布需递增版本。不要用新构建直接覆盖旧版本快照。未来提升存档版本时需防止较旧客户端自动覆盖较新存档；跨版本回退前先保留原始存档，并验证恢复路径。

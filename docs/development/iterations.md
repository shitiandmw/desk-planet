# 持续迭代记录

## 基线：林间聚落 0.1

已有完整球体、天气、六位居民、三种资源、建造、岗位、人口增长、两项研究与本地存档。20 项规则 / 球面 / 天气测试通过，开局可走通。

发现的问题：完成最初三个目标后缺少新目标；材料缺少后续用途；农业只提供产量提升；研究完成仍占人手；进入农业阶段只取决于科技；复杂生产还没有配方与瓶颈反馈。

## 2026-10-19：知识库与下一组迭代

依据：知识库 S01–S09 及补充来源。设计重点是“目标继续推进、农业有布局取舍、材料进入加工链”。

执行顺序：G01–G03 → A01–A03 → M01–M03 → Q01。具体实现、数值和验证结果在完成后追加；未实现的六时代能力保留在开发清单。

当前工作假设：用可见的相邻收益、加工链和阶段成果增加决策；保持温和失败与可恢复性。假设尚需真人试玩验证。

## 0.2 已完成：从田野到机械

已验证 K01、G01–G03、A01–A03、M01–M03、Q01。

1. 建立 12 款游戏、13 个官方来源的知识库，区分来源事实、项目推断和验证证据。
2. 连续四章替代一次性开局目标；满负荷收支、资源来源、配方和定位帮助解决瓶颈。
3. 水井灌溉与粮仓使农业出现集约 / 扩田选择；研究完成释放实际人手。
4. 矿石 → 金属 → 工具 / 零件，真正扣除输入，支持目标库存和缺料恢复。
5. v2 存档兼容 v1，支持导出、导入、损坏文件保护和撤销导入。

结果：30 项测试通过；灌溉与扩田两条数值路线分别为 1123、1087 游戏秒，均达到 12 人、17 座建筑；真实按钮流程约 1078.9 游戏秒完成四章，刷新后保存完全一致。详见[验证记录](../demo-validation.md)与两个 JSON 记录。

### 观察后修订

- 缺矿停工时瞬时消耗归零，会把实际供给缺口掩盖成正增长。改为显示满负荷供给 / 需求，并保留设施当前运行状态；新增回归测试。
- 设施切换沿用旧滚动位置，导致标题被裁切。切换时恢复顶部。
- 高大工业设施可能被树冠遮挡，增加与树冠的选址间距。
- 粮食满仓导致生产暂停，不应阻止有供养能力的聚落接纳居民。迁入使用食物潜在供给判断。
- 合并角色和货物静态网格，保留关节与动画。雨天 17 建筑短采样约 60 FPS，较大负载另列 Q02；不把不同条件的前后样本当作严格加速比。

### 仍需验证的体验

基础木石在工业起步时出现较大盈余；下一轮用原地改造、能源工程等可见用途承接，避免仅提高门槛延长等待。土地和人手的长期压力、目标吸引力及真人的游玩节奏尚需进一步观察。

## 2026-10-20：模型质量、六时代建筑与测试模式

用户要求提升水、地表、树、房屋等模型质量，按发展计划建立各时代建筑，并提供可以直接创建全部建筑的测试模式。

1. 水面与地表：地形场的 GLSL 镜像与 JS 版本逐点一致（新增 2000 点测试）。海水按像素取水深，呈现沙底、焦散、碎浪和柔和的深浅过渡；海滩与湿沙按像素绘制，地形网格加密一倍。
2. 建筑：新的模型工具提供程序纹理、共享材质、圆角体块、木构架、屋顶、门窗、道具和动画标记。12 种可玩建筑重做；新增农耕到星际的 22 种概念模型。设施按材质合并网格，动画部件独立；烟囱和冷却塔的烟由一个实例网格绘制，只在设施运转时出现。
3. 植被与岩石：叶片轮廓减面，树冠加入内部体积和遮蔽明暗；远景树烘焙为 5 种原型实例；山地新增 42 棵针叶树；岩石改为带苔藓的棱面巨石，建筑落成时自动让出占地。小人部件合批。
4. 测试模式：`?test` 或帮助菜单进入。全部解锁、免费即建、资源补足；按时代片区自动布置（每个时代先在自己的片区内打包选址），支持近景查看、移除和清空。测试存档带独立标记与存储键，正式存档拒绝概念建筑。

结果：37 项测试通过（新增 6 项测试模式规则）；`npm run build` 与离线打包通过。浏览器截图逐一检查 34 种建筑近景、六个片区、正面 / 背面 / 海岸、傍晚光照和窄屏测试面板。开局场景由已提交版本的 941 次绘制、899 万三角面降到 645 次、388 万，同时树木由 37 棵增至 79 棵；建满 36 座建筑的测试星球为 1929 次、510 万（软件渲染统计，含阴影与 AO 通道）。

### 观察后修订

- 近景镜头被树木、岩石遮挡：改为射线检测，依次尝试正面斜角、侧面和背面。
- 白色混凝土底座过亮、蒸汽过浓：地面材质整体压暗偏暖，降低蒸汽尺寸与不透明度。
- 生态塔楼的绿化不明显：改为逐层扭转的退台，每层有绿篱、灌木和小树。
- 光滑岩石像鹅卵石：改为棱面着色。
- 星际建筑挤到初始村庄旁：星际片区移到西北平原，各时代先在自己的片区内选址，村庄范围不放后期建筑。

### 仍需验证

真实显卡上的帧率尚未测量（本机为软件渲染）；全部建筑同屏约 1900 次绘制，后续 Q02 可考虑跨建筑合批。概念模型的外观和比例需要用户确认。

## 2026-10-20（续）：流畅度与模型精度

用户反馈：模型精度变化不明显，画面也没有之前流畅。

### 原因

1. 原版就有：SSAO 的预渲染会再画一遍场景，2048² 阴影贴图和它的模糊因此每帧算两次。
2. 第一轮把地形场和噪声放进地面、海面的逐像素着色，海面还加了清漆层。地面加海面的逐像素开销比原版高约 50%；Retina 等高分屏上，这部分占比最大。
3. 像素倍率上限是 1.6，高分屏上画面被放大而发虚；镜头最近只能停在地面以上约 3 个单位，模型细节本来就看不清。

### 改动

- 地形场和草地斑块在启动时由 GPU 烘焙成 2048×1024 贴图（陆地场用两个通道存 16 位，线性过滤仍然精确），地面和海面每像素只取一次样。海面去掉清漆层，焦散只在浅水计算，碎浪只在近岸计算。
- 阴影贴图按需刷新：星球转动时每帧刷新；静止时只有居民和机械在动，约每秒 12 次。云影本来就走独立的 uniform，不触发刷新（本轮中途版本误把天气更新当作刷新条件，阴影仍是每帧重画，已修正）。模糊半径 5 → 3、采样 8 → 6。
- SSAO 以半分辨率计算。画布不再开多重采样和保留缓冲（各通道都在离屏渲染，SMAA 负责抗锯齿；截图在渲染后立即读取）。
- 自动降级：连续约 1 秒达不到 60 帧，像素倍率逐级下调（2 → 1.6 → 1.28 → 1）；到 1 倍后仍慢，每 3 秒依次关闭 SSAO、把阴影贴图降到 1024。启动后 3 秒内不计。
- 启动时预编译全部建筑材质，第一次建造新设施不再卡顿；烟雾粒子减面。

### 精度

- 像素倍率上限 1.6 → 2，高分屏按原生分辨率渲染。
- 阴影视锥跟随镜头可见范围收紧：全景时纹素密度提高约 15%；近景时同一张 2048² 贴图只覆盖几个单位见方，屋檐、栅栏、窗台都有清晰阴影。尺寸分级取值，中心按纹素对齐，缩放时阴影不抖动。
- 建筑纹理以 2 倍密度绘制：灰泥、石材、砖、茅草、瓦、石板、混凝土、铺地、泥地、波纹钢、幕墙、太阳能板，图样不变。树叶纹理同样加倍；草地和道路纹理增加细草叶与碎石。
- 圆柱、球体和旋转体按半径自动加密：大型塔楼、储罐、穹顶的棱面误差控制在 2.5 毫米（模型单位）以内。8 边及以下的刻意棱面保持原样。
- 镜头最近可以到离地约 1 个单位（原来约 3.2）。即时镜头（减少动态效果）下的「近景查看」先更新缩放下限，不会被旧的下限推远。

### 测量

软件渲染（SwiftShader，4 核 CPU）。按 60 Hz 时钟驱动真实帧循环，每帧回读一个像素，保证 GPU 工作计入耗时。早先用 `gl.finish()` 计时，只测到命令提交（3–10 毫秒），作废。数值只用于版本之间比较，不代表显卡上的帧率。

| 版本 | 640×400 每帧 | 1280×800 每帧 | 地面+海面逐像素（每百万像素） | 阴影刷新 | 绘制 / 三角面（每帧） |
| --- | --- | --- | --- | --- | --- |
| 原版 f31d1be | 6928 ms | 6269 ms | 134 ms | 每帧 2 次 | 905 / 898 万 |
| 第一轮 a5a0d13 | 4041 ms | 4424 ms | 202 ms | 每帧 2 次 | 601 / 387 万 |
| 本轮 | 1682 ms | 2024 ms | 96 ms | 15 帧 3 次 | 311 / 203 万（刷新帧 456 / 295 万） |

软件渲染的耗时主要花在顶点和阴影贴图上，屏幕像素占比偏低；显卡上逐像素和后期处理的比重更大。高分屏上本轮按 2 倍像素渲染（原版 1.6 倍），像素多约 56%，地面、海面的逐像素成本仍与原版持平；SSAO 和阴影刷新的减少远大于这部分增加。

### 观察后修订

- 测试截图发现：即时镜头的近景查看会被旧的缩放下限推远（第二轮改为动态下限时引入），已在切换视角时先更新下限。
- 截图检查：全景、聚落、海岸、贴图接缝经线与极点、房屋近景、采食小屋、储物点阴影开关对比、12 种后期建筑近景。烘焙后的海岸、浅滩和碎浪连续，没有接缝；阴影正常（光源在镜头一侧，阴影多落在物体背后）。

### 仍需验证

真实显卡上的帧率需要用户确认；本机只有软件渲染。若仍不流畅，可以先看是否已自动降到 1 倍分辨率并关闭了 SSAO。

### 观察后修订

- 缺矿停工时瞬时消耗归零，会把实际供给缺口掩盖成正增长。改为显示满负荷供给 / 需求，并保留设施当前运行状态；新增回归测试。
- 设施切换沿用旧滚动位置，导致标题被裁切。切换时恢复顶部。
- 高大工业设施可能被树冠遮挡，增加与树冠的选址间距。
- 粮食满仓导致生产暂停，不应阻止有供养能力的聚落接纳居民。迁入使用食物潜在供给判断。
- 合并角色和货物静态网格，保留关节与动画。雨天 17 建筑短采样约 60 FPS，较大负载另列 Q02；不把不同条件的前后样本当作严格加速比。

## 2026-10-20（续）：流畅度与模型精度

用户反馈：模型精度变化不明显，画面也没有之前流畅。

### 原因

1. 原版就有：SSAO 的预渲染会再画一遍场景，2048² 阴影贴图和它的模糊因此每帧算两次。
2. 第一轮把地形场和噪声放进地面、海面的逐像素着色，海面还加了清漆层。地面加海面的逐像素开销比原版高约 50%；Retina 等高分屏上，这部分占比最大。
3. 像素倍率上限是 1.6，高分屏上画面被放大而发虚；镜头最近只能停在地面以上约 3 个单位，模型细节本来就看不清。

### 改动

- 地形场和草地斑块在启动时由 GPU 烘焙成 2048×1024 贴图（陆地场用两个通道存 16 位，线性过滤仍然精确），地面和海面每像素只取一次样。海面去掉清漆层，焦散只在浅水计算，碎浪只在近岸计算。
- 阴影贴图按需刷新：星球转动时每帧刷新；静止时只有居民和机械在动，约每秒 12 次。云影本来就走独立的 uniform，不触发刷新（本轮中途版本误把天气更新当作刷新条件，阴影仍是每帧重画，已修正）。模糊半径 5 → 3、采样 8 → 6。
- SSAO 以半分辨率计算。画布不再开多重采样和保留缓冲（各通道都在离屏渲染，SMAA 负责抗锯齿；截图在渲染后立即读取）。
- 自动降级：连续约 1 秒达不到 60 帧，像素倍率逐级下调（2 → 1.6 → 1.28 → 1）；到 1 倍后仍慢，每 3 秒依次关闭 SSAO、把阴影贴图降到 1024。启动后 3 秒内不计。
- 启动时预编译全部建筑材质，第一次建造新设施不再卡顿；烟雾粒子减面。

### 精度

- 像素倍率上限 1.6 → 2，高分屏按原生分辨率渲染。
- 阴影视锥跟随镜头可见范围收紧：全景时纹素密度提高约 15%；近景时同一张 2048² 贴图只覆盖几个单位见方，屋檐、栅栏、窗台都有清晰阴影。尺寸分级取值，中心按纹素对齐，缩放时阴影不抖动。
- 建筑纹理以 2 倍密度绘制：灰泥、石材、砖、茅草、瓦、石板、混凝土、铺地、泥地、波纹钢、幕墙、太阳能板，图样不变。树叶纹理同样加倍；草地和道路纹理增加细草叶与碎石。
- 圆柱、球体和旋转体按半径自动加密：大型塔楼、储罐、穹顶的棱面误差控制在 2.5 毫米（模型单位）以内。8 边及以下的刻意棱面保持原样。
- 镜头最近可以到离地约 1 个单位（原来约 3.2）。即时镜头（减少动态效果）下的「近景查看」先更新缩放下限，不会被旧的下限推远。

### 测量

软件渲染（SwiftShader，4 核 CPU）。按 60 Hz 时钟驱动真实帧循环，每帧回读一个像素，保证 GPU 工作计入耗时。早先用 `gl.finish()` 计时，只测到命令提交（3–10 毫秒），作废。数值只用于版本之间比较，不代表显卡上的帧率。

| 版本 | 640×400 每帧 | 1280×800 每帧 | 地面+海面逐像素（每百万像素） | 阴影刷新 | 绘制 / 三角面（每帧） |
| --- | --- | --- | --- | --- | --- |
| 原版 f31d1be | 6928 ms | 6269 ms | 134 ms | 每帧 2 次 | 905 / 898 万 |
| 第一轮 a5a0d13 | 4041 ms | 4424 ms | 202 ms | 每帧 2 次 | 601 / 387 万 |
| 本轮 | 1682 ms | 2024 ms | 96 ms | 15 帧 3 次 | 311 / 203 万（刷新帧 456 / 295 万） |

软件渲染的耗时主要花在顶点和阴影贴图上，屏幕像素占比偏低；显卡上逐像素和后期处理的比重更大。高分屏上本轮按 2 倍像素渲染（原版 1.6 倍），像素多约 56%，地面、海面的逐像素成本仍与原版持平；SSAO 和阴影刷新的减少远大于这部分增加。

### 观察后修订

- 测试截图发现：即时镜头的近景查看会被旧的缩放下限推远（第二轮改为动态下限时引入），已在切换视角时先更新下限。
- 截图检查：全景、聚落、海岸、贴图接缝经线与极点、房屋近景、采食小屋、储物点阴影开关对比、12 种后期建筑近景。烘焙后的海岸、浅滩和碎浪连续，没有接缝；阴影正常（光源在镜头一侧，阴影多落在物体背后）。

### 仍需验证

真实显卡上的帧率需要用户确认；本机只有软件渲染。若仍不流畅，可以先看是否已自动降到 1 倍分辨率并关闭了 SSAO。

## 2026-10-20（续二）：后期时代建筑风格

用户反馈：工业、信息、人工智能和星际（用户称「科技时代」）的建筑没有明显的时代风格，看起来太简单，不够科幻。

### 风格

| 时代 | 材质与场地 | 标志元素 |
| --- | --- | --- |
| 工业 | 红砖、铆接铁件、奶白烟囱；卵石场地 | 圆拱铁窗、带箍烟囱、铁轨与蒸汽机车、水塔、输电铁塔与电线 |
| 信息 | 玻璃幕墙、白色竖肋、LED 屏；沥青场地、车位与车辆 | 高层塔楼与停机坪、电视塔、射电天线、洁净厂房与管廊、风机与光伏 |
| 人工智能 | 白色复合外壳、烟色玻璃与青色光带、紫色能量；浅色复合地坪与青色光环 | 神经核心、全息屏、人形机器人与机械臂、无人机、磁悬浮管道 |
| 星际 | 钛合金船体板、不锈钢、橙色警示条；六边形甲板与琥珀光环 | 两级火箭与发射塔、透镜航站楼、着陆光束、轨道电梯、深空天线光束、反重力托架 |

时代之间靠材质、场地和光色区分：工业只有窗灯和路灯，信息是幕墙灯光、屏幕与航空障碍灯，人工智能是青紫光带，星际是琥珀与青色光。

### 改动

1. 模型工具：新增卵石、沥青、复合地坪、六边形甲板、铆接钢板、复合面板、船体板、屏幕、烟色玻璃（带发光层）等程序纹理，纹理只做明暗变化，颜色由顶点色决定；新增青、紫、琥珀发光材质和全息、光束两种半透明材质，半透明部件不投影。
2. 19 种后期概念模型全部重做。代码按时代拆为 `era-industrial.ts`、`era-information.ts`、`era-intelligence.ts`、`era-interstellar.ts`，共用部件放在 `era-kit.ts`；`era-models.ts` 只保留农耕时代模型和注册表。占地半径不变。
3. 近景查看按模型实际高度取景：高大建筑取可见不透明部件的高度（限制在 1.5–3.6），镜头对准一半高度。火箭发射台、现代公寓、通信塔、生态塔楼不再被切掉顶部；光束和全息不计入高度，轨道电梯的缆绳仍按 3.6 截取。
4. 概念建筑说明按新模型重写；建造卡片只显示首句，首句控制在 14 字以内。
5. 阴影：VSM 会把所有接收阴影的网格画进阴影贴图，只关闭 `castShadow` 的全息、光束、透明玻璃和轨道部件其实仍在投影。现在这些部件连同青、紫、琥珀发光材质同时关闭接收，真正离开阴影通道。
6. 减面：后期模型中半径 ≤ 0.02 的圆角只用一段倒角（平滑法线下看起来仍是圆角），风扇叶片、檐下托架等细小件改为直角块。19 种模型的三角面由重做初稿的 38.7 万降到 30.2 万，外观不变。

### 测量

软件渲染（SwiftShader），1280×800，测试星球建满 36 座建筑。每个视角强制刷新阴影，连续渲染 5 帧、每帧回读一个像素，取中位数；两个版本在同一浏览器会话中先后测量，期间不运行其他页面（前一轮测量时另一个游戏页面仍在后台渲染，耗时整体偏高，作废）。表中为绘制次数 / 三角面（每帧，含阴影与 AO 通道）/ 每帧耗时。

| 视角 | 原版 3acf9bb | 本轮 |
| --- | --- | --- |
| 全景 | 1442 / 388 万 / 3215 ms | 1648 / 421 万 / 3285 ms（+2%） |
| 工业片区 | 1451 / 389 万 / 3494 ms | 1654 / 421 万 / 3616 ms（+3%） |
| 信息片区 | 1440 / 384 万 / 3286 ms | 1642 / 414 万 / 3302 ms（+0.5%） |
| 智能片区 | 862 / 293 万 / 2128 ms | 1087 / 322 万 / 2367 ms（+11%） |
| 星际片区 | 1337 / 373 万 / 3571 ms | 1510 / 404 万 / 3584 ms（+0.4%） |

19 种后期模型合计：网格约 180 → 282 个，三角面 17.9 万 → 30.2 万。发光与透明部件离开阴影通道后，全景绘制次数由 1704 降到 1648。概念模型只在测试模式出现，正式游戏的渲染开销不变。

### 观察后修订

- 白天发光部件泛白：ACES 色调映射把高亮自发光压成白色。改为深色饱和底色加中等自发光，光晕改用普通混合。
- 纹理出现彩色噪点：卵石、六边形甲板、铆接钢板改为只做明暗变化；船体板暗板太多，像石砌，减少暗板并调浅。
- 布局遮挡：电站的输电塔与运煤栈桥、工厂的龙门吊、聚变电站的能量塔挡住正面，分别移到侧后方（聚变电站改为 60° / 180° / 300° 布置，控制厅放低在前）；车站多出一道屋脊、货车停到场地外；发射台火箭的暗面朝向镜头。
- 几何错误：实验楼弧形屋顶分段角度错位、内侧弧墙被背面剔除；芯片厂卧式储罐端盖方向错误；聚变线圈首点重复；无人机包裹穿模。
- 近景查看切掉高大模型顶部：见改动 3。
- 测量时关闭发光件投影，绘制次数纹丝不动：排查发现 VSM 的阴影接收者同样进入阴影贴图，见改动 5。

### 仍需验证

各时代风格是否到位需要用户确认。真实显卡上的帧率仍未测量。

## 2026-10-21：海岸白边与居民形象

用户反馈：海水的白色边占比太大；居民形象可以再优化。

### 海岸

岸边发白有两层：泡沫线本身偏宽偏实，外侧还有一圈泛白的浅水。近景取样时，水线一侧是 (232, 229, 221)，相邻的湿沙只有 (211, 202, 157)，浅水比沙滩还亮。原因是海面除阳光和天光外还接受天空环境贴图的漫反射，地面没有这一项，同样的沙色到了水下被照得更亮，经 ACES 映射后接近白色。

1. 泡沫线所在水深由 0.018–0.075 收窄到 0.014–0.046，断开的比例更高，不透明度 0.88 → 0.75；外侧滚浪变细，只出现在 0.03–0.11，强度减半。
2. 浅水透出的海床色由 `#e3d7aa` 压暗到 `#bfb27e`，抵消环境光的额外照明；清澈度衰减系数由 24 调到 30，沙色浅水带收窄。水线一侧现为 (214, 219, 200)。
3. 水线处仍以海床色为主，海面与地形网格的交线照旧不勾边。

### 居民

## 2026-10-22：水面、海滩与岩石（参考 tidewater）

用户要求：分析 [tidewater](https://github.com/dgreenheck/tidewater) 的水和地形为什么好看，在不明显增加渲染开销的前提下，尽量提升地形、岩石、沙滩和水面。

### 借鉴的做法

tidewater 的效果主要来自按物理关系推导颜色，而不是画色带；细节来自一张小的可平铺纹理，在多个尺度上反复取样，并按像素尺寸淡出。本轮按本项目的球面和开销取舍移植了以下几项：

1. 水柱着色：光线沿折射路径往返沙底，按通道衰减（每单位消光 R 6、G 1.15、B 0.52），红光先消失，浅滩自然呈青绿、再到深蓝。替代原来的深 / 中 / 浅三档水色。
2. 共享细节体纹理 `detail-volume.ts`：启动时由 GPU 烘焙一张 64³ RGBA8（1 MiB），四个通道依次是焦散网、泡沫、平滑斑块、细颗粒。以星球空间坐标取样，球面没有接缝，极点也不收缩；海面、海滩、岩石共用。
3. 泡沫：泡沫纹理按覆盖率取阈值，覆盖率低时碎成蕾丝，像素跨过多个气泡后淡为平均覆盖率。水线本身不画泡沫。
4. 冲刷 `shore.ts`：涌浪相位随 √水深 变化（浅水波速），在破浪水深处变成白浪；到达水线的同时，冲刷薄层开始沿沙滩上涌，然后回落，每 7.5 秒一个周期，浪的大小成组变化。海面和地面计算同一个相位。湿沙按 tidewater 的规则变暗、加饱和；刚退水的沙面短暂发亮。
5. 曲面梯度凹凸（高度用星球单位，任意缩放下比例不变）和高光抗锯齿（像素内法线变化越大，粗糙度越高）。
6. 岩石 `rock-material.ts`：风化色斑和颗粒、顶面漂白与淡色地衣、底部堆积沙或土、临海的深色湿带。

抵消开销：海面下始终看不见的海床（三个顶点都低于海平面 0.05）不再进入地形网格。原来这部分先完整着色，再被不透明的海面覆盖，每个深海像素都多算一次地面着色。草地凹凸改用已采样的颜色求导，每像素少三次取样；海滩细节和泡沫纹理只在海滩和泡沫带内读取。

## 2026-10-23：清澈见底的海水

用户的问题：别人的水清澈见底，我们的水在上一轮后好看了，却没有这种效果，原因是什么？先解释，再按建议推进。

### 原因

上一轮的浅滩颜色由海面自己计算：水柱公式里的「沙底」是一个颜色值，画在不透明的海面上。海面下没有真正的东西，看不到海草、礁石和海底阴影，颜色也只是一条平滑的渐变。参考图的清澈感来自真实可见的海底细节：海草、礁石、焦散和海底阴影，再由水按深度吸收。

### 做法

1. 海床重新绘制，并自己完成着色（`terrain.ts`）：沙地、成片的海草丛（0.1 以下开始生长，0.75–0.95 逐渐稀疏）、水流冲出的沙纹、随水深减弱的焦散，以及阴影。最后按通道乘上透过的光（沿折射路径往返）。
2. 海面改为预乘叠加层（`ocean.ts`）：只加入水体散射的光、天空反射和泡沫，透明度为 1 −（1 − 菲涅耳）×（1 − 泡沫）× 海床可见度。海床可见度在 0.45–1 的水深内淡出（`SEABED_FADE`，泥沙遮挡），开阔海面保持深蓝。海面仍在不透明队列中，参与 AO 预通道，renderOrder 1，画在海床之后、透明层之前。
3. 视深（`apparentSeaPointGLSL`）：水下顶点画在折射后看到的位置，深度为 d·cos i /（n·cos t）；俯视约为实际深度的四分之三，越斜越浅。直线视线因此能找到折射光线看到的东西。阴影、图案和吸收仍用真实位置。为了让掠射角下各层保持先后顺序，每层至少位于水面以下一段距离，这段距离随深度增加。
4. 地形分三部分，共用一份顶点缓冲：陆地，海床（水深 1.1 以内，只进颜色通道，不进 AO），深海底（深于 1.1，廉价 Lambert 沙色加吸收，只在视线越过海床外缘时露出）。
5. 视线掠过星球边缘、够不到所画海床的地方（`SEABED_RAY_REACH`），海面自带一层平涂沙底（上一轮的公式），浅滩一直到边缘都保持青绿。
6. 水下的天空光（`seaSkyLightGLSL`）：海床和礁石的水下部分接受与海面相同的天空环境光。光只从水面上方进入，按朝向衰减，礁石侧面比海床暗。水上部分不受影响。
7. 浅水礁石（`planet-nature.ts`）：13 组近岸礁石，每组 2–3 块，位于 0.04–0.22 水深，部分露出水面；水下部分偏藻色，有焦散和吸收。

### 观察后修订

- 第一版在低角度下出现空洞、透过水面看到树、玻璃状的面：直线视线掠过水面后打不到海床。改为按视深绘制水下顶点。
- 地平线附近出现楔形和深色碎面：掠射角下各层挤到一起，于是让最小下沉距离随深度单调增加，并加了边缘判断；粗糙的深海球壳跟不上视深，换成用剔除的三角面做深海底；平涂的深海底与海床之间有接缝，改为受光并按深度吸收。
- 紧贴岸边的海草太密：阈值提高到 0.6，起始水深移到 0.1–0.2。焦散加强。

- 桌面陪伴模式下浅滩发暗发浑：海床只有陆地那份很弱的补光，而上一轮的水柱颜色受天空环境光照亮。对比测试后排除了阴影（关掉海床阴影几乎没有变化），加入水下的天空光后，青绿浅滩恢复，海草仍然可见。
- 天空光最初按各面自己的法线取样，礁石侧面拿到天空贴图最亮的地平线一带，水下部分发白。改为只取上方的天空，按朝向衰减。

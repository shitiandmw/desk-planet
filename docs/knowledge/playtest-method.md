# 试玩和迭代方法

## 每轮固定流程

1. 选一个可描述的体验问题，关联资料和开发项。
2. 写出假设与验收条件，再实现最短可用版本。
3. 规则测试验证守恒、门槛、恢复和存档；数值脚本比较不同合理路线。
4. 浏览器用实际按钮走通新增流程，检查选址、缺工 / 缺料、暂停、刷新与窄屏。
5. 查看全景和近景，核对表现是否对应真实状态。
6. 记录结果、发现的问题和下一项；未完成的内容留在清单中。

## 功能指标

- 所有实际岗位之和不超过人口。
- 消耗和退款不产生负资源或重复收益。
- 无输入不生产；暂停不推进经济；速度作用于同一时钟。
- 从缺粮、停产、取消研究和错误岗位分配中可恢复。
- 章节奖励只能领取一次，进阶依赖实际能力。
- 旧存档迁移保留资源、建筑、岗位和未完成任务；导出 / 导入能恢复。
- 关键操作从可见 UI 完成，触屏确认不被遮挡。

## 需要真人回答的问题

- 不看说明时，30 秒内能否说出当前目标和下一步操作？
- 缺料后能否自己定位原因并解决？哪里需要猜？
- 灌溉与扩建农田之间，是否至少有一次真实考虑？
- 完成一个章节后，是否愿意尝试下一个能力？
- 哪段等待最无聊，哪次变化最有成就感？
- 球体旋转是帮助理解布局，还是增加寻找建筑的负担？

这些是测试问题，不是已经获得的玩家反馈。

## 证据记录

规则检查记录命令与结果；浏览器记录实际操作、关键状态和截图；性能标记视口、人口 / 建筑量、天气、是否暂停以及采样时长。没有实体手机测试时，仅报告窄屏浏览器检查。

# 可操作的设计原则

以下为对来源机制的项目化推断，需用试玩验证。

## 1. 每个新系统回答一个已有问题

先观察玩家当前困境，再决定系统。例如木材满了而无事可做，优先补用途和目标；农业只需重复铺田，优先补布局效率选择。新增建筑不能仅增加目录长度。

验收：加入系统后，能说出它改变的选择、消耗的资源、带来的新能力，以及不用它的替代路线。

## 2. 玩家操作形成因果闭环

看见缺口 → 看见原因 → 能定位来源 → 调整人手 / 建设 / 科技 → 观察改善。

库存、净变化、配方输入和设施状态必须来自同一套经济规则。原料耗尽时，工厂停工并保留尚未完成的劳动进度；不能继续凭空生产。

## 3. 用能力变化组织时代

科技是条件之一，实际生产与工程是另一些条件。农耕文明要出现实际耕作，工业起步要完成加工与机械制造。科技内部允许选顺序，时代不用每个旁支都研究完。

## 4. 空间关系少而清楚

先保持树木 / 岩丘邻近、占地、井与农田覆盖。距离使用球面测地距离，视觉范围与数值相符。一个未说明的隐藏修正比没有修正更难理解。

## 5. 自动执行不等于取消决策

居民负责执行，玩家决定岗位优先级、产业规模和发展目标。研究结束后可释放实际人手，但保留期望岗位，下一项研究仍能请求人手；界面说明其等待状态。

## 6. 储备有价值，也要允许恢复

人口和加工设施消耗资源，材料要有用途。储粮容量限制无目的堆积，让粮仓成为选择。兼容旧存档超出容量的储备：保留已有食物，暂停新增产出直到腾出空间。

粮食短缺先降效，保留采食恢复能力。停止加工必须立即停止耗料。取消建设和研究仅退未用材料，且不重复退款。

## 7. 旧成果继续有用途

农田供养工人，木材可成为冶炼燃料，金属用于工具和机械。新阶段给旧系统新的用途。后期通过升级和自动化释放土地 / 人手，避免每一阶段从头铺同一套基础设施。

## 8. 区分短期体验和长期深度

当前关注：下一步清楚、操作有反馈、失误能恢复、两种合理发展顺序都能推进。

后续关注：区域专业化、生产配比、环境约束、自动化、星际目标。先验证最短链再加复杂度。

## 9. 避免无信息等待

时间成本必须可解释：等待施工、研究、迁入或产料时，提供剩余条件、可做的其他任务和暂停 / 倍速。调高数值不等于增加深度。

## 10. 把“好玩”视为待验证的结果

自动测试证明规则一致；浏览器检查证明操作可完成；真实玩家才能回答目标是否有吸引力、选择是否有意义、节奏是否拖沓。保留不同证据层，不用脚本成功冒充玩家满意。
